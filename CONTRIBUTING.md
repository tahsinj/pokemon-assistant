# Contributing

Solo project, but these rules keep the history and the code readable.

## Branches

- Work on `main`.
- For a big change, use a short branch named after the task (`ui-shell`,
  `sim-engine`) and merge it back when done.
- Branch names describe the work. Never name a branch after a tool, an
  assistant or an agent, and never use generated names.

## Code and docs

- Comments say why, not what. Skip the comment if the code reads fine without
  it.
- No references to plans, phases, specs or options in code ("for the MVP",
  "option C", "for now", "later phases").
- ASCII in comments: `->`, `x`, `>=`, `...`. No em or en dashes, no unicode
  arrows or symbols.
- No filler words: robust, seamless, leverage, honest, deliberately,
  comprehensive, crucial, ensure.
- No tool, assistant or agent names anywhere in the repo: code, comments,
  docs, file names, branch names, commit messages.
- UI strings may use typographic characters on purpose (the middle dot in
  "ESC · CLOSE"), not as decoration. The heading mark comes from the
  `hud-mark` CSS class.

## Styles

- All CSS lives in `src/renderer/src/styles.css`. Tokens (colors, type
  colors, radii) sit at the top as CSS variables.
- Tailwind's theme maps to the same variables: use `text-ink-2`,
  `text-accent-2`, `bg-danger` and so on instead of `text-[var(--ink-2)]`.
- `npm run lint:css` fails on selectors whose classes nothing uses. Delete
  the rule with the component that used it.

## Before pushing

```bash
npm run check     # eslint, prose lint, CSS lint, typecheck, tests
npm run test:ui   # after UI changes: every page at two window sizes
npm run build && npm run test:electron   # after engine or build changes (needs a display)
```

The UI tests run against a production build with a stubbed preload and no
network. Each page is checked for overlapping header controls, clipped or
spilling text, truncated species names, duplicate list rows, raw ability ids
and small or mono-caps sentences. Screenshots land in `test-results/ui/` and
are uploaded by CI; they are for looking at, not pixel-diffed.

## Data

The JSON under `src/renderer/public/data/` and
`src/renderer/src/lib/formSprites.json` is generated and checked in.
Regenerate it with the scripts, never by hand:

- `npm run build-dex`: species, learnsets, moves, items, tiers and bans from
  `@pkmn/sim`, plus EV yields and form sprite ids from PokeAPI.
- `npm run fetch-usage`: usage stats and sample sets per format from the
  pkmn/smogon mirror.
